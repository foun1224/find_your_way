## 0. 誠實聲明（讀前必看）

- **色彩心理學不是硬科學。** 顏色與情緒的關聯多為 **文化慣例與情境依存的聯想（learned associations）**，而非普世因果。學術上跨文化證據最穩健的是「**色溫（warm/cool）與明度（value）→ 喚起程度 arousal / 舒適感**」這一層，個別色相的情緒宣稱（紅=熱情等）證據較弱。
- 因此本文件的色彩理由，**優先建立在較穩固的機制上**：色溫、明度對比、飽和度、光線方向與自然情境的生態聯想（biophilia / 自然場景偏好）。個別色相的聯想以「輔助說明」呈現，不當作定律。
- 需要「保證有效」的地方（可讀性、可辨識性），一律回到**可量化標準**：WCAG 對比度、色盲模擬。

## 1. 色彩系統（Color System）

### 1.1 設計原則

| 原則 | 說明 | 理論依據 |
|------|------|----------|
| 自然場景取色 | 色盤直接取自「晴日山徑」自然光景，而非螢幕原色 | Biophilia hypothesis / 自然場景恢復效果（Attention Restoration Theory, Kaplan） |
| 中低飽和、暖偏向 | 主色盤壓低飽和度、整體略偏暖，避免螢光刺激 | 低飽和＋暖光 → 較低視覺喚起（arousal），服務「放鬆/療癒」 |
| 明度分層講故事 | 用明度（value）而非色相拉出遠中近與晝夜，色相維持和諧 | 空氣透視（atmospheric perspective）；色盲友善（value 不依賴色覺） |
| 焦點靠「暖 × 小面積」 | 大面積冷靜自然色，角色/焦點用一小塊暖強調色 | 色彩對比法則：暖色前進、冷色後退；小面積高彩度＝視覺焦點 |

> HEX 為「正式美術」目標色；像素方格佔位期可直接採用（見 §2）。
> 「聯想」欄是輔助說明，非定律（見 §0）。

| 名稱 | 角色 | HEX | 色溫/傾向 | 選用理由（機制優先） | 聯想（輔助） |
|------|------|------|-----------|----------------------|--------------|

| Cloud Cream 雲乳白 | 雲、留白、亮部 | `#F5EFE0` | 暖白 | 暖白而非純白：降低刺眼、營造柔光；高明度做喘息留白 | 柔軟、安全、日光 |

| Stone Gate Grey 石門灰 | 神秘石門/地標 | `#7C776A` | 中性偏暖灰 | 低彩中性色＝地標不喧賓奪主，靠造型而非顏色吸睛 | 古老、神秘、里程碑 |

### 1.3 功能色（Functional / UI Palette）

> UI 用色極少（見 §3 非侵入）。此處只定義少量系統語意色，且**不以純色相承載狀態**（色盲友善，見 §1.5）。

| 用途 | HEX | 說明 |
|------|------|------|
| 正向/成長提示 | `#F2C14E`（暖陽金） | 沿用主色，避免新色相；搭配「發光/放大」動態而非只靠顏色 |
| 中性資訊 | `#F5EFE0` / `#3A3330` | 暖白底 + 墨棕字 |
| 需注意（極罕用） | `#C56A4E`（陶紅） | 桌寵定位幾乎不需「警示」；若有，配圖示，不單靠紅 |

### 1.4 晝夜與天氣：色溫變化方向（Day–Night & Weather）

**原則**：用**全域色調層（global tint / overlay）與光源色溫**表達時間，而非重畫素材。這服務「時間感＝旅程推進」的核心情感（ADR-003），也讓放置產生「世界在活著」的陪伴感。

理論依據：
- **色溫（correlated color temperature, Kelvin）** 對「暖/冷、放鬆/清醒」的影響是色彩研究中較穩健的一支。
- 呼應人體晝夜節律（circadian）對暖光（夜、放鬆）與冷白光（日間、清醒）的自然聯結——**方向與真實日光一致＝最自然、最無認知負擔**。

| 時段 | 色溫方向 | 明度/飽和 | 全域 tint 傾向 | 情感目標 |
|------|----------|-----------|----------------|----------|
| 黎明 Dawn | 暖、低色溫 (~3000K) | 低明度、低飽和 | 淡粉橘、薄霧 | 甦醒、溫柔開場 |
| 白日 Day | 中性偏冷 (~5500–6500K) | 高明度、中飽和 | 近乎無 tint（基準） | 清爽、清醒、開闊 |
| 黃金時刻 Golden Hour | 暖、低色溫 (~2700K) | 高飽和、長陰影 | 濃暖金橘 | 療癒峰值、最美時刻（適合放正向事件） |
| 黃昏 Dusk | 由暖轉冷 | 飽和快速下降 | 藍紫漸濃 | 收束、沉靜 |
| 夜 Night | 冷、月光藍 (~4100K) | 低明度**但不純黑** | 深藍紫、局部暖窗光 | 安心的獨處，非孤寂 |

- **夜間關鍵**：不用純黑、保留一處暖光點（營火/窗光/角色暖色），維持「有陪伴、不孤單」的社會臨場感（呼應 ADR-002）。
- **天氣**：晴＝高彩高對比；陰＝**降飽和 + 抬高暗部明度（柔化對比）**＝柔和不壓抑；雨＝整體冷偏藍、對比再降、加緩慢粒子。天氣一律往「柔化」走，**不製造戲劇性壓力**（呼應 §3 非侵入 & 準則一療癒）。
- **變化速率**：晝夜過渡以「分鐘級平滑漸變」推進，任一瞬間都察覺不到跳變——對應 §3.4 的呼吸感動效原則。

### 1.5 無障礙（Accessibility）

| 項目 | 規範 | 依據 |
|------|------|------|
| UI 文字對比 | 凡出現**文字/數字**（等級、日誌），與其底色對比 **≥ 4.5:1**（大字 ≥ 3:1） | WCAG 2.1 SC 1.4.3（AA） |
| 非文字 UI 元件 | 可互動圖示/邊界與相鄰色對比 **≥ 3:1** | WCAG 2.1 SC 1.4.11 |
| 不單靠顏色傳意 | 狀態/成長**同時**用形狀、位置、動態、明度冗餘編碼，不只換色相 | WCAG 2.1 SC 1.4.1；色盲友善核心原則 |
| 色盲驗證 | 定稿色盤須通過 **deuteranopia / protanopia / tritanopia** 模擬檢查 | 綠弱/紅弱最常見（男性約 8%） |
| 避開危險配對 | **不用純紅↔綠**承載對立狀態（例：進度好壞）；改用**明度差或藍↔黃** | 紅綠對最易被色盲混淆 |
| 透明度可讀性 | 桌寵疊在任意桌布上——文字元素需自帶底板/描邊，不假設背景色 | 對比不能依賴不可控的桌面背景 |
| 減少動態選項 | 提供「降低動態 reduce motion」偏好；晝夜/粒子可關 | WCAG 2.3.3；尊重前庭敏感使用者 |

> 註：桌寵**角色本身是裝飾性**，色盤美感不受 WCAG 文字標準約束；WCAG 只嚴格套用在「承載資訊的 UI 元素」。這讓美術自由度與可用性各得其所。

## 2. 像素美術規範（Pixel Art Spec）

### 2.1 解析度與像素格

| 項目 | 規範 | 理由 |
|------|------|------|
| 設計座標系 | 以「**邏輯像素 (logical/art pixel)**」為單位設計，非裝置像素 | 與 Retina 解耦，先定美術網格 |
| 縮放策略 | **整數倍縮放 + 最近鄰 (nearest-neighbor)**，禁止非整數縮放與雙線性 | 保持像素邊緣銳利，是像素風的命脈 |
| 顯示縮放建議 | 1 art px ≥ 2 device px（Retina 下常見 @2x/@3x 整數對應） | 小人在高 DPI 螢幕仍看得清、仍「像素」 |
| 全域色數 | 收斂在一個受限調色盤（§1，約 12–24 色）內共用 | 受限色盤＝像素風統一感與復古氣質 |

### 2.2 Sprite 尺寸（佔位規格 → 正式）

| 資產 | 佔位（Phase 1） | 正式（Phase 4） | 說明 |
|------|------------------|------------------|------|
| 主角 Character | **32×32 px** 純色方格 | 32×32（可升 48×48） | 32 是像素風主流基準，動畫成本低、辨識度夠 |
| 旅伴 Companion（若採 OQ-1 雙人） | 32×32 方格（異色） | 略小或等大 | 見 §4 OQ-1 |
| 小物件/地標 | 依網格 16 的倍數 | — | 對齊 16px 網格利於拼接 |
| 圖磚 Tile | 16×16 px | 16×16 | 背景地面以 16 tile 拼接 |

> **佔位期規格明確化**：一個 `#C56A4E`（陶紅）**32×32 實心方格**＝主角；`#8FC7E8` 天空 + `#7FB069` 草地色帶＝背景。此即 Phase 1「會走路的空殼」的美術下限，足以驗收「小人在走、不擋操作」。

### 2.3 動畫 Frame 規範

| 動畫 | Frame 數 | 播放速率 | 依據 |
|------|----------|----------|------|
| 走路 Walk cycle | **佔位 4 格**（contact / down / passing / up）；正式 6–8 格 | **6–8 fps**（偏慢的悠閒步伐） | 4 格是可讀走路循環的下限；低 fps＝從容不趕路，服務療癒 |
| 待機 Idle / 呼吸 | 2–4 格 | **1–2 fps**（極慢） | 幾乎察覺不到的起伏＝「活著、在呼吸」的臨場感 |
| 微反應 Micro-reaction（點擊回應） | 2–4 格 | 起動快（~100–200ms 內有反應），回落慢 | 反應要「即時感」才顯得活；回落慢維持柔和（見 §3.4 的張力取捨） |

- **原則**：**低幀率 + 慢速** 是刻意選擇，與一般動作遊戲「高幀高回饋」相反——目的是把節奏調到「陪你散步」而非「打怪」。
- 走路速度與世界捲動速度綁定，營造「真的在往前走」的旅程感（Phase 2）。

### 2.4 圖層與視差（Layers & Parallax）

由遠到近的 **z-order** 與 **parallax 係數**（1.0 = 隨角色等速，越小越遠越慢）：

| 層 | 內容 | Parallax | 動態 |
|----|------|----------|------|
| L0 天空層 | 天空漸層、日月、遠雲 | 0.0–0.1 | 幾乎不動（最遠） |
| L1 遠景 | 雪峰、山靄（Snow Peak / Peak Haze） | 0.15–0.25 | 極慢飄移 |
| L2 中景 | 丘陵、樹線、石門地標 | 0.4–0.5 | 緩動 |
| L3 近景地面 | 山徑、草地圖磚（角色所踩） | 0.9–1.0 | 主捲動層 |
| L4 前景 | 近處草叢、可遮住角色腳部 | 1.1–1.3 | 略快於角色（越近越快） |
| L5 角色層 | 主角（＋旅伴） | — | 走路循環，畫面焦點 |
| L6 氛圍層 | 光暈、天氣粒子、晝夜 tint overlay | 覆蓋全畫面 | §1.4 |
| L7 UI 層 | 極簡資訊/互動（見 §3） | 螢幕固定 | 隨需出現 |

- **理論**：**motion parallax** 是最強的深度線索之一；分層越多、係數階梯越平順，縱深與「翻山越嶺」的空間感越真。
- **技術銜接**：L7 UI 建議為獨立 overlay（SKNode 或另一 NSWindow），與世界層解耦，確保 UI 永遠可讀、可 hit-test（細節屬 `04_ARCHITECTURE.md`）。

## 3. UI/UX 原則（桌寵非侵入設計）

### 3.1 最高原則：Calm Technology（平靜科技）

本產品是**整天常駐**的軟體，因此奉 **Calm Technology（Mark Weiser & John Seely Brown；Amber Case 系統化）** 為 UI 最高框架：

> 資訊應能**在中心（focus）與邊陲（periphery）之間平順移動**；常駐工具**預設待在邊陲、不索取注意力**，只在被需要時才進入中心。

三條可落地的非侵入戒律（不得違反）：
1. **不得遮擋**：預設佔畫面一角、極小 footprint，不壓在使用者工作區之上。
2. **不得干擾**：不搶焦點（never steal focus）、不彈 modal、不強制打斷；非互動區**點擊穿透**到桌面（呼應 ADR-002）。
3. **不得製造壓力**：無倒數、無「未完成」紅點、無愧疚感提示（呼應 ADR-003 純放置）。

### 3.2 具體 UI 規則表

| 維度 | 規則 | UX 理論依據 |
|------|------|-------------|
| 尺寸 Size | 桌寵預設高度 ≤ 螢幕高 ~10–15%，角落錨定；使用者可縮放/移動 | 邊陲存在感 = Calm Tech；小面積＝低干擾 |
| 透明度 Opacity | 視窗透明；閒置一段時間可**微降透明度/靜default**，滑鼠靠近再回滿 | 邊陲↔中心平順轉移（Calm Tech）；降低長時視覺負荷 |
| 資訊密度 Density | **預設零常駐文字/數字**。等級、里程不長駐顯示 | Miller's law（減少同時資訊）；attention economy（每則常駐資訊都在收「注意力稅」） |
| 出現時機 Timing | 提示為**環境式、稀疏、非模態**；偵測到使用者處於全螢幕/專注 App 時自動退場 | 中斷成本理論（interruption cost）；尊重心流 |
| 選項數量 Choices | 任一介面同時可見操作 ≤ ~5 | Hick's law（選項越多決策越慢，違背「低負擔」） |
| 資訊揭露 Disclosure | 詳情（旅程日誌、數值）**hover/點擊才展開**（progressive disclosure） | Progressive disclosure；先 glanceable 後 detail |
| 整體質感 Aesthetics | 投資在「一眼美、耐看」 | Aesthetic-usability effect（美的介面被感知為更好用、更被包容） |
| 互動命中 Hit target | 少數互動點（如點角色）命中區要**夠大、就在視線焦點上** | Fitts's law（目標越大越近越好點）——角色本身即大目標 |

### 3.3 資訊呈現：等級/旅程/狀態用什麼視覺語言

**核心方針：用「世界的變化」說話，用數字說話是最後手段。** 成長的正回饋靠時間感/旅程感/偶發事件營造（ADR-003 明訂），因此：

| 要表達 | 主要視覺語言（glanceable、克制） | 次要（progressive disclosure 展開後） | 依據 |
|--------|-----------------------------------|--------------------------------------|------|
| 等級/成長 | **角色外觀漸變**（裝備、色澤、姿態）、**背景場景推進**（走過的地貌變了） | hover 顯示等級數字/稱號 | 具象成長 > 抽象數字；符合「默默前行」 |
| 旅程/里程 | 走過的**路徑縮影/地標剪影**、遠方目標山門越來越近 | 點開「旅程日誌」時間軸 | 空間隱喻承載進度，天然 glanceable |
| 狀態/心情 | 角色**姿態與微動作**（散步、歇腳、看風景）、晝夜氛圍 | — | 動作即狀態，零文字 |
| 正向事件 | **短暫**的暖陽金光暈 + 慢放大 + 輕音，數秒即散 | 可於日誌回顧 | peak-end：偶發高光點強化整段陪伴的回憶 |

- **禁止**：常駐血條/經驗條/紅點/百分比 HUD——這些是「任務型遊戲」語言，與療癒定位相悖。
- **數字的位置**：需要精確值的使用者仍能取得，但**藏在一層互動之後**，不對所有人強制曝光。

### 3.4 動效原則：緩慢、有機、呼吸感

| 原則 | 做法 | 為何服務療癒 |
|------|------|--------------|
| 緩慢 Slow | 過場、tint、環境動態走「分鐘/秒級」慢曲線 | 慢節奏降低喚起（arousal）、誘發放鬆（副交感傾向） |
| 有機 Organic | 用 **ease-in-out** 與輕微不規則，避免機械等速與生硬直線 | 自然界少有等速直線；有機曲線＝生命感、不焦躁 |
| 呼吸感 Breathing | 待機用極緩的縮放/起伏 loop（如呼吸） | 「還活著、在陪你」的低度臨場感，無需索取注意 |
| 無突兀回饋 No jolt | **禁止** overshoot 彈跳、閃爆、螢幕震動等高刺激特效 | 這些是 dopamine-hit 遊戲語言，與「低負擔陪伴」衝突 |

- **一個誠實的張力（給 Fable 留意）**：互動回饋有個經典取捨。**Doherty threshold** 說回饋 < ~400ms 才顯得「即時、掌控感」；但療癒定位又要「慢」。
  **建議解法**：**互動的「起動」要即時（點下去 <200ms 內角色有反應）以維持『活著、聽得到我』，但動作的『回落/收尾』放慢**——即時但不急躁。環境/氛圍動效則一律慢。這樣兼顧「responsive（有回應）」與「calm（不催促）」。

## 4. 待決問題的設計觀點（供 Fable 定案，Opus 不拍板）

### OQ-1 — 單人 vs 一主一伴的視覺呈現

**設計觀點（利弊，不定案）：**

| 方案 | 視覺呈現構想 | 服務的情感 | 代價/風險 |
|------|--------------|------------|-----------|
| A 純單人 | 一名旅人；靠「環境的生機」（風、鳥、光）避免孤寂 | 純粹的「我與我的旅程」、投射自我 | 長時間掛著可能偏孤單；陪伴感靠環境撐 |
| B 一主一伴（呼應靈感圖兩人同行） | 主角 + 一名**次要旅伴**：略小/略後/明度略低，構圖上不搶主角焦點 | **社會臨場感（social presence）最強**——「有人與你同行」，最貼合核心願景那句「有人陪你走」 | 需多一套 sprite/動畫；雙人構圖與互動要調 |
| C 單人起步、旅伴為「旅程中相遇」 | 前期單人，成長到某里程「遇見」旅伴加入 | 把「陪伴」變成**被賺得的偶發高光**（peak 事件） | 敘事/系統成本較高（屬 Phase 3 偶發事件） |

**Opus 傾向**：情感目標白紙黑字是「**有人陪你走**」，故**視覺語言應為 B 的味道**，但**用 C 的節奏引入**最動人——單人啟程、旅伴於旅途相遇並同行。構圖上務必用**大小/前後/明度**確立主從（角色陶紅最暖最前，旅伴稍退），避免雙焦點打架。**請 Fable 拍板：一開始就雙人（B），還是相遇式引入（C）。**

### OQ-3 — 互動點的視覺可供性（Affordance）

**設計觀點（不定案）：** 桌寵的互動須符合 ADR-003「**邀請，非強迫**」。因此可供性要**若隱若現、可被發現但不催促**。

理論工具：Norman 的 **affordance（能做什麼）/ signifier（暗示線索）** 之分——我們缺的其實是**signifier**。

| 候選信號 | 做法 | 依據 | 評價 |
|----------|------|------|------|
| 游標變化 | 滑鼠移到角色上 → 游標變手型/心型 | 最低成本的標準 signifier | ✅ 建議必做 |
| 靠近微反應 | 指標接近 → 角色**輕轉頭/眨眼/停步看你** | 用「生命回應」暗示可互動，零 UI 元件 | ✅ 建議必做（最貼療癒） |
| 稀疏 rim-light | 偶爾一圈極淡暖光呼吸，暗示「可以摸我」 | 弱信號、不常駐、不干擾 | ⭕ 可選，須極克制 |
| 常駐按鈕/圖示 | 角色旁掛操作按鈕 | 傳統但**違反非侵入**（常駐 UI＝注意力稅） | ❌ 不建議常駐 |

**Opus 傾向**：**以「角色的生命反應」作為主要 signifier**（游標變化 + 靠近時的微反應），**不掛常駐按鈕**；互動集合先極小（點一下 → 角色暖心回應一次），命中區大（整個角色，Fitts's law）。**請 Fable 拍板：最小互動集合到底包含哪些**（純點擊回應？餵食？對話？）——這也回扣 OQ-3 的原題。
