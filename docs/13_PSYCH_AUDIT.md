## 〇、一句話總結

**目前的體驗把「一段旅程」做得很好，但把「一個活著的同伴」做得還不夠。** 現況的角色幾乎只有「持續走路」一個行為，臨場感（`02` §2）與回應性（`02` §4）——也就是**陪伴感的兩根主柱**——是最大的未兌現空間。且諷刺的是：**旅伴（Companion）目前比主角（Character）更有生命力**（旅伴有「偶爾看向你」的微行為，主角完全沒有）。下一輪投資應集中在「讓角色像真的在那裡活著、且察覺到你在」，這比任何新美術或新系統都更直接服務核心情感目標。

**素材現況的關鍵事實**：素材表含 4 向（右/左/前/後）走路，但**程式目前只接了 `right_*`**（`CharacterNode`/`CompanionNode` 都只讀 `prefix: "right_"`）。這代表**「轉身面向你」這種最有陪伴力的微行為，很可能不需要新畫格**——素材已在，只差切圖與接線（見下方誠實註記）。

## 一、CP 值最高的前 3 項（給 Fable 的重點）

> 判準：最能深化「陪伴 × 療癒」、且務實可做（考慮現有素材限制）。

### ★1. 主角自主微行為 + 待機呼吸（§2 社會臨場感、§2.3 待機規範）
把主角從「永遠走路循環」升級為「有生活節奏地活著」：偶爾停下看風景、歇腳、伸懶腰、**偶爾轉頭看向使用者**，以及最基本的**待機呼吸**（極緩縮放 loop）。這是**最高 CP**：它打在 `02` §2「陪伴感強度取決於角色是否像真的在那裡活著（自主微行為、有生活節奏、偶爾看向你）」的正中心，而目前主角**一項都沒有**。成本大多不需新美術（呼吸=scale loop；歇腳=暫停走路循環+站姿；看向你=用素材表既有的 `front_` 幀）。

### ★2. 靠近 / 游標回應性（§4 依附之回應性）
目前角色**只有「點擊」才回應**；游標靠近沒有任何覺察。但 `03` §4 與 ADR-006 都白紙黑字把「靠近微反應」列為**建議必做**的 signifier，且執行檔層的 `ClickThroughController` **已經在追游標位置**（做動態點擊穿透用）——回應性的基礎設施半數已存在。加一個「游標接近 → 角色輕轉頭 / 停步看你」是**低成本、高依附回報**：依附的核心是**回應性 (responsiveness)**（`02` §4），而「你靠近，它就察覺到你」正是最溫柔的回應。

### ★3. 可回顧的旅程日誌（§5 敘事認同、`03` §3.3 progressive disclosure）
目前旅程日誌是**短暫 toast，約 3.5 秒即消失**（fadeIn 0.4 + hold 2.5 + fadeOut 0.6），看過即逝。但 `02` §5 敘事認同的核心是「把時間累積成**一個連續的故事**」，`03` §3.3 也明列「點開旅程日誌時間軸」為 progressive disclosure 的正解。**離線回來錯過的日誌、走過的地標、相遇的那一刻，目前都無法回顧**——故事被說了卻沒被保存。這是 §5 最大的結構性缺口。列為 top 3 是因為**戰略價值高**，但須誠實：**成本最高**（需一個可召喚的面板），且**設計上最靠近紅線**（見下方 P3 的紅線註記）。

> **若只能做兩項**：做 ★1 + ★2。這兩項合計成本中低、幾乎不需新美術、直接把「陪伴」從「一段旅程」升級為「一個活著且在乎你在的同伴」，是本次審視最划算的投資。★3 是更大的戰略投資，可獨立排期。

## 二、完整優先清單（高 → 低）

### P1 — 主角自主微行為 + 待機呼吸 ★CP最高

- **現況**：`CharacterNode` 只有一個 `walkCycle`（`walkFrameOrder [3,2]` 兩幀循環）+ 點擊時的 `playWarmResponse`（跳一下+放大）。**沒有待機、沒有歇腳、沒有看風景、沒有看向使用者、沒有呼吸**。角色從開機到關機永遠在走同一個循環。
- **心理學缺口**：`02` §2 明講「陪伴感的強度，取決於角色的臨場質感：它是否**像真的在那裡活著（自主走動、有生活節奏、偶爾看向你）**」；§2.3（`03`）也規範了「待機 / 呼吸 1–2fps 極慢起伏＝活著、在呼吸的臨場感」。目前主角**缺整個「生活節奏」維度**——它是一台走路機器，不是一個同伴。（對照：`CompanionNode` 反而有 `runOccasionalLookAtCompanion` 微行為，主從生命力顛倒。）
- **具體建議**（考慮素材限制）：
  1. **待機呼吸**（零新美術）：一個極緩的 `scale` loop（如 1.0↔1.015，週期 3–4s，ease-in-out），永遠疊在走路之上或走路暫停時啟用。呼應 `03` §3.4「呼吸感」。
  2. **偶爾歇腳 / 看風景**（零新美術）：每隔一段隨機時間（如 40–90s，用 `wait(forDuration:withRange:)`），**暫停走路循環數秒**、停在站姿——「走累了停一下看看四周」。純節奏變化即有生活感。
  3. **偶爾看向使用者**（**用素材既有 `front_` 幀，非新畫格**）：低頻（如每 1–3 分鐘一次）短暫切到面向前方的幀 1–2 秒再轉回。這是 §2「偶爾看向你」的**字面實現**，也順勢服務 §4 回應性。
  4. （可選）**伸懶腰**：若素材無對應幀，可用純 scale/skew 近似或延後；**此項若需新畫格要講明**——目前素材表未確認含此動作。
- **理論依據**：`02` §2（社會臨場感 / 擬社會關係——自主微行為、生活節奏、偶爾看向你）、`02` §1（SDT relatedness）、`03` §2.3 / §3.4（待機呼吸、有機動效）。
- **實作成本**：**低—中**。呼吸/歇腳＝純 `SKAction`，零美術；看向你＝切圖接線既有 `front_`（見誠實註記）。無新系統、不動 `GameState`。
- **紅線**：**無風險**。純表達性、非侵入、不索取注意力（趴著的貓，`02` §二總綱）。反而降低「機械感」。

### P2 — 靠近 / 游標回應性 ★CP次高

- **現況**：回應只發生在 `mouseDown`（`GameScene.mouseDown` → `triggerWarmResponse`）。游標**靠近但未點擊**時，角色毫無反應。`ClickThroughController`（執行檔層）已在追游標以切換 `ignoresMouseEvents`。
- **心理學缺口**：`02` §4 依附的三要素是**一致性 / 可及性 / 回應性**；回應性目前只在「點擊」這個較重的動作上兌現。但依附是靠「你在場我就察覺得到」的**細膩、低門檻回應**養成的。`03` §4（OQ-3 設計觀點）與 ADR-006 都把「靠近微反應（指標接近 → 角色輕轉頭 / 停步看你）」列為 **✅ 建議必做**，目前**未實作**——這是規格已認可卻缺席的功能。
- **具體建議**：
  1. **游標接近 → 溫和覺察**：當游標進入角色周圍一個較大的半徑（比命中框大），觸發一次**比點擊更輕**的反應——停步、（用 `front_` 幀）轉頭看你、或一次極淡的呼吸加深。**不要用點擊那種 hop**（避免頻繁觸發變吵）。
  2. **游標變化**（若尚未做）：游標移到角色上變手型/暖色——最低成本的 Norman signifier（`03` §4 表列 ✅ 建議必做）。`ClickThroughController` 已知道游標何時在角色上，接線成本低。
  3. **節流與克制**：靠近反應要有 cooldown（如已進入過就不重複觸發，離開再進才重置），避免游標在角色附近游移時角色一直抽動——**克制是療癒的一部分**（`02` §2「臨場 ≠ 打擾」）。
- **理論依據**：`02` §4（依附之回應性 / 可及性）、`02` §2（臨場感，但須守「≠打擾」）、`03` §4 表（affordance/signifier，✅建議必做）、ADR-006。
- **實作成本**：**低—中**。基礎設施（游標追蹤）部分已在；主要工作是在執行檔層把「游標接近」事件接到場景的一個新 `playProximityAcknowledgement()`。
- **紅線**：**需注意但可守**。回應必須是「因為你來了，我很開心」，**不是**「你該來了」（`02` ADR-006 / §4）。務必**不給任何功利回報**（不加速、不解鎖），且**不可頻繁抽動變成討拍**（`02` 紅線三）。守住「克制 + 零功利」即安全。

### P3 — 可回顧的旅程日誌 ★CP（戰略型，成本較高）

- **現況**：日誌是 `showJourneyLog` 的短暫 toast（約 3.5 秒淡出即移除）。離線回歸的多行日誌、章節轉場、相遇文案，**播完就永久消失**，無任何回顧入口。
- **心理學缺口**：`02` §5 敘事認同——療癒來自「把不可控、片段的日常，重新框架為**一段有方向、在前進的旅程**」，而旅程要成為「**一個連續的故事**」需要**被保存、可回看**。目前「故事」只存在於稍縱即逝的 toast，使用者無法「翻閱我們一起走過的路」。`03` §3.3 明列「點開旅程日誌時間軸」為此的 progressive disclosure 正解。
- **具體建議**：
  1. **持久化日誌條目**：把已發生的地標 / 事件 / 相遇 / 章節寫進一個可讀清單（資料多半已在 `GameState`：`eventsEncountered`、地標、`companionJoined`、章節可由 distance 衍生）。
  2. **可召喚、非常駐的面板**（progressive disclosure，`03` §3.2 Disclosure）：從選單列或點角色以外的手勢喚出一個安靜的時間軸，**預設不顯示**（守 Calm Tech 邊陲原則）。
  3. **語氣沿用敘事留白**（`02` §5）：只記「走過了○○ / 那天遇見了同伴」，**不要**做成「成就清單 / 收集進度 / X/Y 完成度」。
- **理論依據**：`02` §5（敘事認同、留白可投射）、`02` §3（漸進成就的柔性呈現）、`03` §3.2 §3.3（progressive disclosure、glanceable→detail）。
- **實作成本**：**高**。需新 UI 面板（另一 overlay 或視窗）、召喚手勢、資料整理成可讀時間軸。是本清單唯一的「新系統」。
- **紅線**：**需注意**。這是最容易不小心把「陪伴」做成「待辦/收集」的地方——
  - ❌ 不可出現「完成度 %」「收集 X/Y」「還差 N 個」——會製造 FOMO 與功利感（`02` 紅線二、§7）。
  - ❌ 不可用「你已 N 天沒回來看日誌」之類提示（紅線三）。
  - ✅ 純粹的、只增不減的、溫柔的回憶錄。守住此界線才可做。

### P4 — 長期成長的外觀可見性（§3 成長、`03` §3.3）

- **現況**：成長靠**章節 toast + 世界推進**（走過的地貌變了）。`GrowthStage` 有邏輯，但只驅動章節名文字。**角色外觀從頭到尾不變**。
- **心理學缺口**：`02` §3（勝任 / 漸進成就）+ §4（依附：「同一個它長大」）——長期成長應「**看得見**」。`03` §3.3 明列「等級/成長 → **角色外觀漸變（裝備、色澤、姿態）**」為主要視覺語言。目前長期陪伴下來，**角色看不出「我們一起走了很遠」**，成長的具象載體缺席。
- **具體建議**：極克制的外觀漸變——如**很久之後**多一件小配件（旅人的斗篷/背包磨舊）、或姿態隨章節微調。**必須是「同一個它長大」**（§4 一致性），不是換一隻。
- **理論依據**：`02` §3（漸進成就、掌控感）、`02` §4（依附一致性「同一個它長大」）、`03` §3.3。
- **實作成本**：**高，且受素材限制**。**需要新畫格**（配件/姿態變體 × 走路幀 × 方向），這是新繪美術，非接線既有素材。**誠實說明：此項在補齊美術前無法做**，故排序在回應性之後。
- **紅線**：低風險，但外觀變化**不可**綁「你要常回來才長得出來」（紅線六）——必須純由 distance（時間）驅動，離線同樣會長。

### P5 — 旅伴回應性升級 + 主角回望旅伴（§2 / §4）

- **現況**：`CompanionNode.runOccasionalLookAtCompanion` 用一次 `scale(1.03)` 脈衝**近似**「看向主角」（其實只是放大一下，並非真的轉頭）；主角**從不回望**旅伴。兩人同行卻無**相互**的關係表現。
- **心理學缺口**：`02` §2 / §4——「兩人同行」把陪伴視覺化的力量，來自**彼此有回應**（旅伴看主角、主角偶爾也看旅伴）。目前是各走各的、單向假動作，關係的臨場感未完全兌現（ADR-004 的 (a) 投射模式期望「一伴會看向主角、會在主角休息時停下」）。
- **具體建議**：
  1. 旅伴「看向主角」改用素材既有 `front_`/`left_` 幀做**真的轉頭**，而非 scale 假動作。
  2. **主角歇腳時，旅伴也停下**（呼應 §4「在主角休息時停下」）——把 P1 的歇腳與旅伴行為**耦合**，成本很低卻極大提升「他們是一起的」。
  3. （可選）主角偶爾**回望**旅伴一眼。
- **理論依據**：`02` §2（社會臨場感）、`02` §4（回應性）、ADR-004（主從投射、一伴的回應性）。
- **實作成本**：**低—中**（若 P1 已建歇腳機制，此項多為耦合與換幀）。
- **紅線**：無風險。

### P6 — 環境的細微生機（§6 ART soft fascination）

- **現況**：晝夜、天氣、雨絲已做（很好，直擊 ART）。但地面道具（`PropScatter`）是**靜態**裝飾，天空層無緩慢生物/雲的自主飄移；**近景草叢不搖曳**。
- **心理學缺口**：`02` §6 ART 的「soft fascination（柔性魅力）」來自**不費力可看的緩慢自然動態**（雲、鳥、草動）。目前的「活著感」幾乎全靠角色，環境本身偏靜。加一點極慢的環境生機能強化「世界在活著」的恢復性凝視（也順帶降低對角色的注意力集中）。
- **具體建議**：極慢、低密度的環境動態——如偶爾一隻鳥緩緩飛過（可用簡單 shape 或既有道具）、雲極慢飄移、近景草叢受「風」極輕搖曳（純 `SKAction` 位移/旋轉）。全部**慢到可以放著不看**（`02` §6 節奏原則）。
- **理論依據**：`02` §6（ART、soft fascination、低喚醒）、`03` §1.1（biophilia / 自然場景恢復）。
- **實作成本**：**低—中**（草搖曳/雲飄＝純動效；飛鳥若無素材可用簡單形狀或延後）。
- **紅線**：無風險；須守「慢、不搶注意」（`02` §6 / 紅線六）。

## 三、低喚醒 / ART 節奏複查（§6）

**結論：節奏整體正確、偏慢、無明顯高喚醒點。** 逐項查：

- 走路 ~5fps、晝夜連續漸變、天氣 crossfade 4–6s、雨絲 3.2–4.6s 慢落、相遇 peak 1.4–2s 慢放大無 overshoot、暖心回應 hop 僅 +5px/0.3s——**全部落在低喚醒象限**（`02` §6、`03` §3.4「無 jolt」）。✅
- **唯一可留意點（非缺陷）**：離線回歸的 2.5s catch-up 捲動會「一開始跑比較快」（`PROGRESS_LOG` 已註記為設計內、可調緩）。目前 `progress` 是線性，觀感上開頭偏快。**建議（極低優先）**：把 catch-up 的 `customAction` 進度改為 ease-in-out，讓回歸補間也「有機、不急躁」（`03` §3.4）。這不是紅線問題，純觀感 polish。

## 四、六條紅線複查（§二 / §7）

**結論：現有機制無踩線，把關良好。** 逐條：

| 紅線 | 複查結果 |
|------|----------|
| 一：不罰離開 | ✅ 離線只增不減、12h cap、`wasCapped` 不呈現成損失（`GameScene.journeyLogTexts` 註解明載）。線上=離線同速有迴歸鎖測試。 |
| 二：不製造 FOMO | ✅ 事件掛確定性里程軸（非變動比率）、錯過會在後續里程遇到、無限時。 |
| 三：不負向催促 | ✅ 日誌語氣留白溫柔（「又走了一段路」），無愧疚語、無紅點、無推播催回。 |
